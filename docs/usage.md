# Экономика AI-запросов

Расход запросов к Gemini через воркер (лимит free tier: 20/день на модель,
цепочка из трёх моделей ≈ 60/день; текущий расход — `GET /health` воркера,
поле `usedToday`; жёсткий потолок — DAILY_HARD_CAP в wrangler.toml).

| Действие | Запросов | Что уходит |
|---|---|---|
| Скан этикетки | 1–3 | S1 (распознавание) + S6 (глубже о вине) + S2 (справка винодельни — только если винодельня НОВАЯ; повторные вина той же — из кэша wineries) |
| Ручное добавление вина (с сортом/регионом) | 1–2 | S6 при первом открытии карточки + S2 для новой винодельни |
| Дегустация | 2 | S3 (вопросы при открытии опросника) + S4 (мнение об оценке после сохранения) |
| «Обновить справку» винодельни | 1 | S2 с перезаписью |
| Винная карта (будущее, P18) | 1 | S5 (кэш по хэшу фото, 24 ч) |

Vivino-запросы (шлюз в Яндекс Облаке) в лимиты Gemini не входят: кэш 30 дней
в aiCache, «обновить данные Vivino» идёт мимо кэша.

Невалидный JSON от модели → воркер делает один повтор — считается как ещё
один запрос Gemini (в usedToday не виден: стоп-кран считает вызовы /ai).
